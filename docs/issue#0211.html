Implementation Notes

Issue #211 — Prevent recoverable tool errors and late plans from corrupting successful Run progress — 2026-07-31

Design Decisions

Decision Separate warning, recovered, and unresolved failure scopes

Ambiguity: A capability can contain both successful evidence and a later failed optional request.

Choice: Keep recoverable attempts warning-only until their request-family budget is exhausted, and only let unresolved failures that affect required evidence influence the terminal outcome.

Rationale: This preserves genuine partial outcomes without allowing an unsupported optional format attempt to invalidate complete, validated, and delivered evidence.

Decision Persist safe diagnostics as a runtime event

Ambiguity: The issue required richer Admin observability but did not require a new database schema.

Choice: Emit deepagents.runtime.outcome and derive a field-whitelisted failure summary from the persisted event.

Rationale: Existing Run steps already preserve runtime events, so this keeps rollout migration-free while preventing tool arguments or credentials from leaking through the Admin API.

Decision Enforce planning at the business-tool boundary

Ambiguity: Prompt guidance alone could not guarantee that plan_execute creates a plan before business work.

Choice: Reject business tools with INITIAL_PLAN_REQUIRED until a successful write_todos call establishes the initial plan.

Rationale: The invariant is deterministic, applies only to plan_execute, and does not mistake a failed plan write for a valid plan.

Decision Disable the framework default subagent structurally

Ambiguity: Deep Agents treats subagents=[] as permission to install its default general-purpose subagent.

Choice: Register a LensGateway harness profile with the general-purpose subagent disabled, retain the deny middleware as defense in depth, and pin deepagents==0.6.12.

Rationale: General Chat no longer receives contradictory task guidance, while modes that explicitly provide the fast subagent retain their existing behavior.

Deviations

None — the implementation follows the issue body and its confirmed follow-up defect, including the suggested scoped runtime, frontend reconciliation, observability, and harness-profile changes.

Tradeoffs

Tradeoff Semantic late-plan migration instead of discarding activity

Alternatives: Keep the synthetic task, discard all pre-plan activity, or migrate activity into formal tasks.

Choice: Match activity families to formal tasks in stable order, then remove the synthetic top-level node.

Reason: This preserves useful execution detail and the five-task total, at the cost of a deliberately bounded heuristic for legacy late-plan sequences.

Tradeoff Version pin instead of a broad compatibility range

Alternatives: Continue allowing any Deep Agents version above 0.2.0, maintain a SourceLens fork, or pin the verified release.

Choice: Pin 0.6.12 and cover its compiled agent stack with an integration test.

Reason: A pin makes production behavior reproducible with minimal maintenance, but future framework upgrades must be explicit and test-gated.
