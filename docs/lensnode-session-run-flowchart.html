SourceLens 的 Session 负责保存消息，每个用户轮次被拆成独立 Run。 本图展示从事务创建、Celery 派发、LensNode 接纳、Checkpoint、Deep Agent 执行到终态确认的完整闭环，并展开网络断连、进程崩溃、恢复、取消、超时和停机路径。

STATE MODEL

三层状态各司其职

  • Run：用户可见生命周期
  • RunExecution：派发与恢复协议
  • RunStep：结构化执行轨迹
  • RUNNING + resume_by 表示等待恢复

ADMISSION PROTOCOL

三阶段避免假恢复

  • DISPATCHED：只证明 Channels 已发布
  • run_admitted：LensNode 已创建任务
  • checkpoint_ready：可从持久状态恢复
  • 每次重派使用新的 dispatch_id

RECOVERY SAFETY

恢复默认失败关闭

  • 从未接纳：Fresh requeue
  • 已接纳且就绪：同 UUID 恢复
  • Checkpoint 不完整：明确失败
  • 未完成非幂等写禁止重放

IMPORTANT BOUNDARY

Outbox 只跨连接存活

  • 当前 outbox 是进程内 deque
  • WebSocket 重连可以重放
  • 进程崩溃后依赖 SQLite Checkpoint
  • 终态 ACK 后才清理本地状态
