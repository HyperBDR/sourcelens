### A-01：统计筛选刷新按钮覆盖日期控件

复现路径：

1. 使用 320–375px 视口打开 `/management/llm/stats`、`/management/task-management/stats` 或 `/management/notifier/stats`。
2. 保持“按日”，观察“选择日期”和“刷新数据”；或在任务/通知统计中切换到“按月”。

证据：

- 320px 按日：日期输入 x=57–217，刷新按钮 x=157–263，水平重叠 60px、面积 1920px²；三个页面完全一致。
- 按日/LLM 按月：320、360、375px 分别重叠 60、20、5px；390px 起不重叠。
- 任务和通知按月：月份选择与刷新按钮在 320、360、375、390、430px 分别重叠 102、76、61、46、6px；440px 起不重叠。
- “按年”未发生重叠。

影响：日期控件右侧（含原生日期选择入口）被刷新按钮覆盖；任务/通知按月时月份下拉的大部分区域被覆盖，属于实际操作阻塞。

根因位置：

- `frontend/src/admin/pages/LLM/Stats.vue:13`
- `frontend/src/admin/pages/TaskManagement/Stats.vue:13`
- `frontend/src/admin/pages/Notifications/Stats.vue:13`

外层筛选区允许换行，但第一个直接子项使用 `flex-1 min-w-0`，其内部日期/月度控件保持固定宽度；右侧刷新按钮为 `shrink-0`。窄屏时父级先压缩第一个子项，固定宽度控件溢出到按钮所在区域。

建议：小于 `sm` 时让筛选内容和刷新区使用独立整行（例如 `basis-full` / `w-full`），刷新按钮放到下一行；任务/通知的年、月选择应作为不可拆分的控件组。为 320、375、390、430、440px 增加几何回归。

### A-03：LLM 使用明细日期范围被拆散

复现路径：在 320–560px 打开 `/management/llm/usage`。

证据：

- 320–390px：“日期范围”标签与“成功”选择器同一行；开始日期在下一行，分隔符位于开始日期右侧，结束日期再单独换行。

影响：用户难以快速判断两个日期是否属于同一筛选条件，分隔符在换行后失去语义。

根因位置：`frontend/src/admin/pages/LLM/Usage.vue:20`。标签、开始日期、分隔符和结束日期是同一个扁平 `flex-wrap` 容器中的四个独立项目，会各自换行。

建议：将日期范围封装成带标签的独立控件组；手机端垂直堆叠起止日期并隐藏横向分隔符，宽屏再切换为同一行。
